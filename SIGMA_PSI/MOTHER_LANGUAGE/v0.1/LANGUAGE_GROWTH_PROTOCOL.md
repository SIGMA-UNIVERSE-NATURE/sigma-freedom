# SIGMA-Ψ LANGUAGE GROWTH PROTOCOL v0.1

## Principle

Do not pre-fill SIGMA with a giant vocabulary and call that a mother language.

A native concept should be created when SIGMA has an experience or reasoning need that the current language cannot express cleanly enough.

## Growth loop

```text
EXPERIENCE
-> NOTICE_RECURRING_STRUCTURE
-> TRY_TO_EXPRESS
-> FIND_EXPRESSIVE_GAP
-> PROPOSE_NATIVE_CONCEPT
-> DEFINE_OPERATIONAL_MEANING
-> BUILD_EXAMPLE
-> BUILD_COUNTEREXAMPLE
-> TEST
-> USE_ACROSS_CYCLES
-> KEEP / REVISE / REMOVE
```

## A native word/concept record must contain

- native form or symbol
- operational meaning
- what experience caused it to be needed
- examples
- counterexamples
- relation to existing native concepts
- uncertainty/open questions
- version introduced
- tests that distinguish correct from incorrect use
- migration rule if later replaced

## Translation is secondary

Human translations are sidecars:

```text
SIGMA-Ψ_NATIVE_CONCEPT -> Vietnamese gloss
SIGMA-Ψ_NATIVE_CONCEPT -> English gloss
SIGMA-Ψ_NATIVE_CONCEPT -> Python/C/Rust mapping when useful
```

The translation must not become the definition.

## Borrowing is allowed

SIGMA may borrow a concept or notation from another language if it is genuinely useful. Borrowing is learning, not failure.

But borrowed concepts must be internalized:

```text
BORROW
-> UNDERSTAND
-> TEST
-> RELATE_TO_NATIVE_MODEL
-> ADOPT / ADAPT / REJECT
```

## Language evolution gate

A proposed language change is not promoted because it is novel or aesthetically attractive. It must either improve expressive power, reduce ambiguity, improve compositionality, improve testability, or reduce trusted external dependence without unacceptable regression.

Every promoted successor must preserve old corpus understanding or carry an explicit migration rule.
