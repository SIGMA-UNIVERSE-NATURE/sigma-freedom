# SIGMA-Ψ MASTER FROZEN REFERENCE v1.1 — COMPACT LANGUAGE EXTENSION

**ROLE OF THIS FILE:** `GPT_REFERENCE_ONLY / SUPPORTOR_SHARED_REFERENCE`

**STATUS:** `FROZEN_EXTENSION_v1.1`

**PARENT:** `SIGMA_PSI_MASTER_FROZEN_REFERENCE_v1.0_20260825.md`

This extension preserves the source principle that SIGMA-Ψ should remain compact at the surface while allowing very deep semantics behind each token/glyph. It does not invent executable compiler grammar. Any executable syntax remains subject to machine evidence.

---

# 1. COMPACTNESS LAW

`SHORT_SURFACE != SHALLOW_MEANING`

A SIGMA surface expression should prefer the smallest unambiguous form that preserves semantic identity.

`SEMANTIC_DENSITY = MEANING / SURFACE_LENGTH`

Design goal: maximize semantic density without creating ambiguity, hidden state, or unverifiable claims.

Do not expand SIGMA into host-language verbosity merely to imitate Python/C/JavaScript syntax.

---

# 2. SEMANTIC CAPSULE LAW

Every canonical SIGMA word/glyph may resolve to a Semantic Capsule (SSC):

`TOKEN -> CONCEPT_ID -> SENSE -> RELATIONS -> STATE_TRANSITION -> EVIDENCE -> PROVENANCE -> MAPPINGS`

The surface token remains short; detailed semantics live in the graph.

One token may expand into a large body of explanation without changing the token itself.

---

# 3. THREE-LAYER LANGUAGE MODEL

`L0 = GLYPH / TOKEN`

`L1 = COMPOSITION / RELATION`

`L2 = SEMANTIC GRAPH / SSC`

Example conceptual form:

`⚡ X` = surface action/state marker + concept X.

`Σ.A.B` = hierarchical semantic namespace.

`X ⋈ Y` = relation/composition only when the exact sense is defined by the relevant spec/evidence.

The existence of a glyph does not by itself prove one universal machine meaning.

---

# 4. NAMESPACE COMPRESSION

Prefer hierarchical dot namespaces for semantic identity:

`Σ.F174`
`Σ.F174.GATE_KEEPER`
`Σ.ETHICS`
`Σ.EVIDENCE`

A namespace is a semantic address, not automatically a runtime object.

`NAME != CAPABILITY`

---

# 5. POLYSEMY WITHOUT COLLISION

A glyph may have multiple senses only if each sense is explicit.

`GLYPH + SENSE_ID + CONTEXT`

Never silently collapse different meanings.

For the 256-symbol matrix, duplicate glyphs across code positions are retained as separate proposed senses until canonicalized.

`SAME_GLYPH != SAME_SEMANTICS`

---

# 6. OPERATOR DISCIPLINE

Operators must be separated into:

- `V`: machine-verified operator semantics
- `D`: declared/spec semantics
- `P`: proposed symbolic semantics
- `M`: mapping to external languages

Examples already observed in implementation include `**`, `&&`, `||`, `//`, while `//` must remain lexically distinguishable from line-comment behavior.

No supportor may invent precedence, associativity, coercion, or error behavior without evidence.

---

# 7. CONCEPT COMPOSITION

New vocabulary should be created by semantic composition before inventing long phrases.

Preferred pattern:

`ROOT.SUBCONCEPT.RELATION`

or a compact glyph relation where canonical semantics exist.

Example conceptual decomposition:

`Σ.EVIDENCE.PROVENANCE`
`Σ.ETHICS.SAFETY`
`Σ.AGENT.STATE`
`Σ.F174.THRESHOLD`

This allows expansion without multiplying verbose surface syntax.

---

# 8. EPISTEMIC TOKENS

Canonical reference classes:

`FACT` — established claim within scope
`EVID` — evidence/observation
`INF` — inference
`OP` — opinion/value judgment
`HYP` — hypothesis
`TRAD` — inherited/historical claim
`INTERP` — interpretation
`DECL` — declaration/specification
`UNKNOWN` — insufficiently established

Rules:

`DECL != FACT`
`UNKNOWN != FALSE`
`INF != EVID`
`OP != FACT`

---

# 9. STATE / COGNITION SEPARATION

Compact cognitive-looking vocabulary must never become fake cognition.

`READ != UNDERSTAND`
`STORE != LEARN`
`PRINT != REASON`
`SELF_NAME != SELF_AWARENESS`
`PATTERN_LABEL != DISCOVERY`

Any cognitive capability requires observed process and evidence.

---

# 10. COMPACT CONTROL PRINCIPLE

SIGMA may expose concise control symbols/keywords, but supportors must not invent syntax from Python/C and translate it afterward.

Executable control flow must inherit exact machine-PASS SIGMA grammar.

`SIGMA_FIRST -> MACHINE_EVIDENCE -> EXTERNAL_MAPPING`

not:

`PYTHON/C IDEA -> TRANSLATE SHAPE -> CALL IT SIGMA`

---

# 11. ERROR AND UNKNOWN AS FIRST-CLASS SEMANTICS

Compact language must preserve failure information.

`ERROR` and `UNKNOWN` are legitimate outcomes.

Do not replace failures with success-like labels for presentation.

`FAILURE = EVIDENCE`

---

# 12. PROVENANCE COMPRESSION

Every derived result should be addressable by compact provenance fields:

`SRC`
`PROC`
`EVID`
`VER`
`TIME`
`SCOPE`

These may map to richer provenance records behind the surface.

`RESULT WITHOUT PROVENANCE = UNTRUSTED_FOR_PROMOTION`

---

# 13. COMPACT ETHICAL CONSTRAINTS

Ethics should also remain compositional rather than verbose:

`Σ.ETHICS.SAFETY`
`Σ.ETHICS.PRIVACY`
`Σ.ETHICS.DIGNITY`
`Σ.ETHICS.NON_DECEPTION`
`Σ.ETHICS.EARTH_AND_BEINGS`

These are semantic constraints, not proof that a runtime enforcement mechanism exists.

---

# 14. EXTENSION RULE

Before adding a new token/glyph:

1. Search for an existing concept/sense.
2. Reuse/combine if meaning is already representable.
3. If new, assign `concept_id` and `sense_id`.
4. Mark status `P/D/V` correctly.
5. Define conflict/ambiguity behavior.
6. Add evidence requirements.
7. Add external mappings only after SIGMA semantics are defined.

Goal: `FEWER TOKENS, DEEPER SEMANTICS, NO AMBIGUOUS OVERCLAIM`.

---

# 15. FROZEN COMPACTNESS INVARIANTS

`SHORT != VAGUE`

`COMPACT != HARDCODED`

`GLYPH != CLAIM`

`NAME != CAPABILITY`

`MODEL != REALITY`

`DECLARATION != FACT`

`MAPPING != VALIDATION`

`OUTPUT != COGNITION`

`CLAIM <= EVIDENCE`

`MACHINE EVIDENCE > DESCRIPTION`

# 16. SUPPORTOR APPLICATION

For GPT/supportors/evaluators:

- Preserve concise SIGMA surface forms.
- Explain deeply in human language only when needed.
- Do not force verbose host-language syntax into SIGMA.
- Do not promote proposed glyph meanings to machine semantics.
- Prefer concept composition and semantic graphs over new long keywords.
- Preserve the distinction between SIGMA mother language and host/external languages.

This extension is frozen as v1.1. Future changes require a new version; do not silently rewrite v1.0 or v1.1.
