# SIGMA V4-C3 R2 — NATIVE HUMAN-READABLE OBSERVER REPORT V1

Date: 2026-09-05 Asia/Ho_Chi_Minh

## Purpose

V4-C3 R1 proved that native SIGMA can commit a machine report and next plan before a real 180-second native pause, expose the committed report while the VM remains paused, preserve the plan across the pause, and resume afterward.

The current report is audit-oriented and difficult for a human observer to understand. V4-C3 R2 adds a second report surface generated by native SIGMA from the same committed machine evidence.

The machine report remains canonical and unchanged in role.

`MACHINE_REPORT=CANONICAL_AUDIT_EVIDENCE`

The new observer report is a native presentation layer only.

`OBSERVER_REPORT=NATIVE_SIGMA_FORMATTED_VIEW_OF_MACHINE_EVIDENCE`

## Non-negotiable boundary

The host must not translate, summarize, infer meaning, choose a report sentence, compute a semantic score, or rewrite the next plan.

`HOST_REPORT_SUMMARIZATION=NO`

`HOST_REPORT_TRANSLATION=NO`

`HOST_SELF_ASSESSMENT=NO`

`HOST_NEXT_WORK_SELECTION=NO`

`HOST_SEMANTIC_INTERPRETATION=NO`

`HOST_LEARNING=NO`

All report interpretation policy must execute in native `.sigma` under the locked VM. Host may only launch the native observer reporter after an exact native report boundary and display exact reporter output bytes.

## Two-layer report contract

### Layer 1 — machine evidence

Keep exact structural/audit state such as:

- cycle id;
- progress budget state;
- discovered/profile/complete/hold/evidence counts;
- C2 phase/status;
- active document;
- B4 context/token cursor;
- exact last structural evidence;
- exact native plan;
- claim limits.

### Layer 2 — human observer view

The observer view should answer, in plain language:

1. What is SIGMA doing now?
2. Which document/context is it currently processing?
3. What text did it just process, using a bounded exact preview?
4. What structural span was strongest in the latest committed learner evidence?
5. How wide was that span and how many structural-support occurrences were observed in the current window?
6. How many stored documents are discovered/profiled/completed/held and have evidence?
7. Is there a HOLD condition?
8. What exact next plan did native SIGMA select, plus a fixed native explanation of that plan code?
9. What is not proven, especially semantic understanding and truth validation?
10. How long is the observation pause before automatic resume?

## Structural wording rule

The report may say:

- `strongest structural span`;
- `repeated structural support`;
- `current corpus completion count`;
- `current plan`;
- `current unresolved HOLD`.

It must not rewrite an n-gram/span as a semantic proposition or claim that SIGMA understands the concept represented by those words.

`STRUCTURAL_SPAN != SEMANTIC_CONCEPT`

`SUPPORT_COUNT != TRUTH_CONFIDENCE`

`CORPUS_COVERAGE != UNDERSTANDING_PERCENT`

## Percentage policy

Do not display an invented `understanding %`.

The human report may display exact machine counts immediately. A future numeric `CORPUS_COVERAGE_PERCENT` may be added only after its arithmetic path is separately runtime-admitted.

Keep:

`UNDERSTANDING_PROXY_PERCENT=NOT_COMPUTABLE_FROM_CURRENT_MACHINE_EVIDENCE`

`SEMANTIC_UNDERSTANDING=NOT_PROVEN`

## Native reporter first implementation

Create a separate native observer reporter that reads only committed C2/B4/C3 state and prints a bounded human-readable view.

Initial fields:

- cycle index;
- C2 phase;
- active document;
- B4 context id;
- bounded context text preview;
- strongest `BEST=` structural span extracted from the exact B4 evidence record;
- width and support counts from B4 compact unary memories;
- corpus document/profile/complete/hold/evidence counts computed natively;
- exact native plan;
- native fixed explanation for each admitted plan code;
- pause seconds;
- explicit claim-limit lines.

The reporter performs no learning and no work selection.

`REPORTER_LEARNING=NO`

`REPORTER_WORK_SELECTION=NO`

`REPORTER_TRUTH_DECISION=NO`

`REPORTER_SEMANTIC_INFERENCE=NO`

## Later C3-R2 controller extension

After the observer reporter is admitted, extend the controller with a bounded per-cycle touched-document ledger so the report can say exactly which document IDs were touched during that cycle rather than only the active document at reflection time.

The touched-document ledger must be:

- native-owned;
- bounded;
- deduplicated natively;
- reset only after successful reflection/pause completion;
- provenance-only, not a host-generated activity list.

## Admission sequence

1. native human observer reporter source + isolated dynamic preflight;
2. prove exact bounded context preview and `BEST=` extraction under locked VM;
3. prove native count display and native plan-code explanation;
4. integrate reporter at the C3 report boundary while the 180-second native pause is in progress;
5. add bounded touched-document ledger in a new C3 controller revision;
6. real-corpus reflective continuous run;
7. restart/resume gate;
8. only later consider production promotion/cutover.
