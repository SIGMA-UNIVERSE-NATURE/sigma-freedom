```text
CANDIDATE||<native_status>||FORM_A||<native_form_a>||FORM_B||<native_form_b>||SUPPORT||<native_support>
```


Observation input is exact VNM-03/VNM-02-compatible bytes:

```text
OBS||obs_id||FORM||surface||LEFT||opaque_left||RIGHT||opaque_right||SOURCE||source_id
```

VNM-04 emits one file only:

```text
output/vnm01_input_bundle.memory
```

with first line:

```text
HYPOTHESIS||<native_derived_id>||FORM_A||<candidate_a>||FORM_B||<candidate_b>
```

and subsequent lines:

```text
EVIDENCE||<native_derived_id>||<observed_a>||<observed_b>||SOURCE||<native_preserved_provenance>
```

Single-file output is deliberate: it avoids a two-file partial-write window inside VNM-04. The runner may later perform exact mechanical record routing into VNM-01's two files.

## Native structural policy

A raw evidence pair is eligible only when:

```text
forms_are_distinct
AND exact_LEFT_RIGHT_context_matches
AND at_least_one_form_is_candidate_member
```

VNM-04 does not label the pair SUPPORT/COMPETING. It emits the raw observed pair. Admitted VNM-01 performs that native classification and weight update downstream.

Consistency gate:

```text
SUPPORT_PAIR_COUNT == VNM02_NATIVE_CANDIDATE_SUPPORT
```

Mismatch => refusal.

