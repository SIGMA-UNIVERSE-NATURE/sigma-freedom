# C5 Native Internet Gateway Sidecar V1 — Source Ready

## Runtime evidence before this patch

Oppo outbound HTTPS preflight observed HTTP 200 from `https://example.com/`, `https://www.wikipedia.org/`, and `https://api.github.com/`, with TLS verification result 0. This proves device outbound HTTPS reachability for the tested endpoints only.

The running C5 V3 learner remains PID 20026 in the tested session. This gateway revision is designed as a hot sidecar and does not require replacing or restarting the running C5 V3 process.

## Purpose

Broaden C5 V3 external acquisition beyond the existing Wikipedia-only adapter while preserving SIGMA-native cognitive ownership.

Production path:

1. Observe an exact external query already generated by native C5 V3.
2. Mechanically transport that exact query to DuckDuckGo HTML discovery.
3. Mechanically decode a bounded candidate list without host ranking or semantic selection.
4. Compile and execute `SIGMA_C5_NATIVE_INTERNET_SELECTOR_V1.sigma` with the locked SIGMAC / locked VM. Native SIGMA selects the candidate index by a generic query-overlap rule, with a native stable fallback if overlap is zero.
5. Mechanical bridge maps only the native-selected index to the exact URL.
6. Refuse non-HTTPS or non-global destinations; perform bounded HTTPS fetch, preserve raw bytes, mechanically extract textual material, hash provenance, and atomically publish the decoded document to the existing C5 V3 external cache path.
7. Existing C5 V3 remains the only component that can later admit that cache through its existing external-fetch path. `FETCHED_EQUALS_LEARNED=NO` remains.
