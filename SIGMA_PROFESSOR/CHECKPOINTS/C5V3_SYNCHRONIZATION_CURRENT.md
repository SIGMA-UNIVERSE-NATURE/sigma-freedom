R2 changes the recovery semantics materially: if the supervisor dies but its worker survives, the replacement supervisor validates and adopts that worker rather than spawning a duplicate AUTO loop.

Recovery Anchor R1:

```text

COMMIT=c0724d20729bde28c80f8bcb816e375ad332f1b8
```

Recovery hierarchy:

```text
AUTO worker
<- Persistent Supervisor R2
<- Recovery Anchor R1
<- Android JobScheduler periodic ensure, when Termux:API is available
<- Termux:Boot boot-time ensure, when Termux:Boot is installed
```

Android scheduler is a recovery backstop, not a real-time watchdog. On Android N+ the periodic minimum is approximately 15 minutes. Force-stop survival is not claimed because Android can suppress app processes/jobs/receivers until the app is permitted to run again.
